# 儿童成长打卡产品总规划

> 产品名称：待定。名称冻结前，不提交公众号或小程序认证。
>
> 本文用于统一产品、研发和公众号运营口径。凡标注为“后续阶段”的能力，均不得作为第一版对外卖点。

## 1. 产品定义

这是一个面向家庭的儿童成长打卡工具。家长把每天要完成的小任务拆清楚，孩子完成后主动打卡，家长确认并给予积分，孩子再用积分兑换自己设定的愿望。

核心闭环：

`任务设置 → 孩子打卡 → 家长确认 → 积分入账 → 愿望兑换 → 下一个任务`

产品不把孩子当作被管理对象，而是帮助家庭把“提醒、完成、鼓励、兑现”变成可持续的日常协作。

### 服务对象

- 主要决策者：有日常陪伴需求的家长。
- 使用者：家长与孩子；第一版以一个微信账号内的双视图使用为主。
- 适用任务：学习、运动、习惯、生活；学习可标记为学校任务或家庭任务。

### 不做什么

- 不做公开排行榜、同伴比较、惩罚性扣分或社交晒娃。
- 不采集孩子真实姓名、学校、定位、照片、音视频或作业附件。
- 不把积分包装成现金、存款、理财或任何金融产品。

## 2. 品牌与对外表述

名称尚未确定。名称选择标准：短、顺口、儿童易理解、能承接“每日任务完成”的业务价值，并完成微信名称和商标检索后再认证。

名称确定前，对外统一使用以下描述：

> 孩子的每日任务打卡工具：完成小任务，获得小鼓励，慢慢养成好习惯。

避免使用“银行”“消消乐”等可能引发金融合规或知识产权风险的词语。

## 3. 第一版（家庭 MVP）

### 3.1 产品目标

验证一个家庭是否愿意连续使用“任务—打卡—确认—积分—愿望”的闭环，而不是一次性完成大量功能。

### 3.2 用户角色与权限

| 角色 | 第一版能力 | 边界 |
| --- | --- | --- |
| 家长 | 创建家庭和孩子档案；设置任务、积分和愿望；审核打卡；查看账本；确认兑换 | 家长 PIN 仅防止同设备误操作，不是独立身份认证。 |
| 孩子视图 | 查看今日任务；提交打卡；查看积分、愿望和兑换状态 | 无法编辑任务、审核、调分或兑现愿望。 |

第一版不提供教师、机构、多账号家长协作、群组或作业附件。

### 3.3 功能范围

| 模块 | 第一版交付 | 关键规则 |
| --- | --- | --- |
| 家庭设置 | 创建家庭、孩子昵称、6 位家长 PIN、孩子视图切换 | 仅保存昵称；家长 PIN 不保存明文。 |
| 每日任务 | 学习、运动、习惯、生活四类；每日、每周、一次性周期 | 学习任务可标记学校任务或家庭任务。 |
| 孩子打卡 | 查看当日应完成任务并提交 | 同一孩子、同一任务、同一天只能有一次有效打卡。 |
| 家长审核 | 通过或驳回，并可写简短说明 | 只有审核通过才发放积分。 |
| 积分账本 | 审核发分、人工加/扣分、兑换扣分均留痕 | 家长不直接改余额；每次调整必须写原因。 |
| 愿望池 | 家长创建愿望和兑换所需积分；孩子申请兑换；家长确认兑现 | 兑换时冻结/扣除积分，取消时原路退回。 |
| 家长中心 | 审核队列、任务管理、愿望管理、积分账本、身份切换 | 孩子视图看不到家长操作入口。 |

### 3.4 关键体验原则

- 孩子首页只出现“今天该做什么”和一个明确的打卡动作，避免复杂表格。
- 任务宜小、明确、可验证，例如“阅读 20 分钟”而不是“认真学习”。
- 家长审核要及时；超过一天未审核应提示家长，不催促孩子。
- 奖励以鼓励和兑现为主；不允许公开比较，不把扣分作为常规管理方式。

### 3.5 第一版验收

- 新家长在 3 分钟内完成家庭、孩子、PIN 和 3 个任务的设置。
- 孩子能独立找到今日任务并完成一次打卡。
- 重复打卡、重复审核、重复兑换都不会重复记分或扣分。
- 家长能说清每一笔积分的来源与去向。
- 全流程不需要域名、独立服务器、Web 管理后台、支付、AI 或文件上传。

## 4. 后续产品路线

| 阶段 | 触发条件 | 新能力 | 不可省略的治理 |
| --- | --- | --- | --- |
| V2 家庭协作与小组 | 第一版验证连续使用后 | 多家长/多孩子账号、家庭邀请码、学习小组、教师白名单发布任务 | 监护人授权、最小化可见范围、教师不能获得无关家庭数据。 |
| V3 商用管理 | 出现明确的机构付费和运营需求后 | 管理后台、机构分组、数据导出、基础报表、权限审计 | 导出审批、下载留痕、按机构隔离数据、删除与保留策略。 |
| V4 智能成长建议 | 已积累可信的结构化任务和审核数据后 | 周报、薄弱项提示、家长可编辑的 AI 建议 | 单独授权、明确“建议非诊断”、人工可覆盖、禁用画像售卖。 |
| V5 App | 小程序留存和复杂使用场景证明需要后 | App 端、推送与更完整的离线体验 | 复用统一账号、权限和数据边界，不重建业务规则。 |

### 教师与机构进入 V2 的规则

- 教师只能通过家长/机构管理员邀请加入白名单，不开放陌生人搜索加入。
- 教师可发布任务给授权的组，默认不可见孩子积分、家庭愿望、其他家庭资料。
- 作业图片、音视频在需要前不采集；一旦启用，必须单独设计保存期限、查看权限与删除机制。

### 数据后台与导出进入 V3 的规则

- 家长侧：先提供本人家庭的任务、打卡、积分账本导出。
- 机构侧：只看已授权学生的聚合数据，默认不展示私人愿望和家庭备注。
- 管理后台以运营与客服为目的，不得成为读取所有儿童明细的万能入口。

## 5. 商业化原则

第一版不收费、不接广告、不接支付；先验证留存和家长愿意持续设置任务。

后续可按两条线发展：

1. 家庭会员：更多孩子/家长协作、可复用任务模板、成长周报、历史导出等增值能力。
2. 机构 SaaS：教师任务发布、班级管理、授权报表、运营后台；按机构或活跃学生收费。

底线：不出售儿童个人信息，不以儿童行为数据投放广告，不把积分兑换为现金或金融权益。

## 6. 技术与上线边界

### 固定技术选择

- 客户端：原生微信小程序 + TypeScript。
- 后端：微信云开发 CloudBase，使用小程序原生云函数调用和云数据库。
- 第一版不购买独立服务器、不使用阿里云或腾讯云 ECS/RDS、不建设 HTTP API。
- 第一版不需要自有域名；域名仅可作为品牌保护资产后续购买，不接入第一版业务。
- 运营入口：公司主体认证订阅号，用于高频内容发布并关联小程序。

### 认证与发布顺序

1. 定名称并在微信后台实际校验可用性。
2. 注册企业订阅号和小程序；小程序完成企业认证后再开通正式云开发环境。
3. 完成隐私政策、儿童个人信息规则、家长删除入口和小范围内测。
4. 真机测试、提交小程序审核、灰度邀请首批家庭。

## 7. 公众号内容运营方案

### 7.1 公众号定位

面向家长，提供可直接照做的儿童任务设计、习惯养成和亲子鼓励方法；小程序是把方法落地的工具。

不把公众号写成“卖软件的公告栏”。内容先帮助家长解决“每天催不动、任务不清楚、奖励难坚持”的问题，再自然引导使用产品。

### 7.2 固定内容栏目

| 栏目 | 内容 | 目标 |
| --- | --- | --- |
| 今日小任务 | 一条可直接复制的学习、运动、习惯或生活任务 | 高频获客与收藏。 |
| 学习好习惯 | 阅读、作业、复习、书包整理的任务拆解 | 覆盖学校与家庭学习场景。 |
| 运动加油站 | 跳绳、体能、户外、亲子运动的低门槛任务 | 避免产品被误解为只管作业。 |
| 生活小能手 | 早睡、收纳、家务、自理的小任务 | 建立家庭日常使用频率。 |
| 家长小方法 | 如何设任务、给积分、审核、兑现愿望 | 提升家长成功率和留存。 |
| 一周回顾 | 一周完成情况、复盘问题、下周任务模板 | 引导形成固定使用节奏。 |
| 产品公告 | 内测招募、使用教程、版本更新、隐私说明 | 仅在必要时发布，不能取代内容。 |

### 7.3 一周发布节奏

| 日期 | 栏目 | 示例选题 |
| --- | --- | --- |
| 周一 | 学习好习惯 | 把“写作业”拆成 3 个孩子愿意完成的小任务。 |
| 周二 | 今日小任务 | 今天的 10 分钟书包整理挑战。 |
| 周三 | 运动加油站 | 不用器材的 8 分钟亲子运动任务。 |
| 周四 | 家长小方法 | 积分不是贿赂：怎样设置才不会失效。 |
| 周五 | 生活小能手 | 晚饭后自己收餐具的任务卡。 |
| 周六 | 亲子挑战 | 一家人一起完成的周末小任务。 |
| 周日 | 一周回顾 | 用 3 个问题和孩子复盘这一周。 |

### 7.4 首批 12 篇内容题目

1. 孩子不是不自律，很多时候是任务太大。
2. 一张“今日小任务卡”，让催促少一点。
3. 写作业前先完成这 3 个小步骤。
4. 积分应该怎么给，孩子才不会只盯着奖励？
5. 阅读 20 分钟，怎样变成孩子愿意主动做的事？
6. 不用买器材，也能完成一次亲子运动打卡。
7. 孩子做完了但家长没看见，鼓励为什么会失效？
8. 周末家务任务，按年龄这样分更容易完成。
9. 愿望池怎么定，既有期待又不变成讨价还价？
10. 不要用扣分管孩子：可以这样处理没完成的任务。
11. 开学后，学校任务和家庭任务怎样不打架？
12. 一周只设 3 个任务，反而更容易坚持。

### 7.5 内容发布标准

- 每篇只解决一个真实问题，给出一个可执行任务示例。
- 不用“治好拖延”“提升成绩”等结果承诺；不制造家长焦虑。
- 不展示儿童真实姓名、照片、学校、成绩单或聊天记录。
- 产品仍未上线的功能不写进案例和海报；教师协作、AI、导出、支付均属于后续阶段。
- 每篇结尾只有一个动作：保存任务、评论分享经历，或申请内测，不同时堆多个入口。

## 8. 近期工作清单

1. 名称暂缓认证，先形成 5 个候选并完成微信名称、商标类别检索。
2. 使用现有 V1 规格和实施计划搭建小程序与 CloudBase 开发环境。
3. 完成隐私文档与家长删除流程，再邀请 5–20 个真实家庭内测。
4. 先积累 12 篇公众号内容，至少连续发布两周，再用内测反馈调整选题。
5. 连续观察 3 周：家庭任务创建率、孩子打卡率、家长审核时效、周留存和愿望兑换率。
