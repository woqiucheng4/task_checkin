## 1. 设计目标

以用户确认的“果园日计划”参考图为唯一主视觉方向，为成长果园平台建立一套覆盖全角色、可长期扩展的 UI 系统。

产品应像一本温暖、自然、可信赖的成长手账，而不是常见的渐变卡片式积分应用。孩子能直观看到“完成真实任务让果树成长”；成人能快速完成布置、审核和管理；机构、平台与内容方能在高信息密度场景中保持同一品牌识别。

核心目标：

1. 孩子在首页立即看懂今天要做什么、完成后会得到什么成长反馈。
2. 家长、教师和助教用尽量少的步骤完成布置、审核和例外处理。
3. 机构、平台和内容方在电脑后台完成批量、表格和治理操作。
4. 视觉层完全复用既有业务 API、ViewModel 和权限规则，不在页面重新计算业务状态。
5. 同一设计语言同时适合低年级和高年级小学生，不幼稚，也不成人化。

## 2. 产品端与角色分工

采用用户确认的双端架构。

### 2.1 原生微信小程序

服务以下高频移动角色：

- 孩子
- 家长/家庭管理员
- 教师
- 助教

优势是日常触达、扫码入组、拍照提交、拍照识别、审核提醒和角色切换自然。

### 2.2 Web 管理后台

服务以下高信息密度角色：

- 机构管理员
- 平台运营人员
- 第三方内容服务方

优势是表格筛选、批量建班、权限配置、统计、导出、工单、套餐和内容管理更高效。

### 2.3 跨端一致性

两端共用品牌颜色、字体层级、插画语言、状态语义、间距体系和组件命名。移动端强调触控与成长反馈；管理后台强调信息密度、批量效率和治理可审计性。

## 3. 视觉语言

### 3.1 总体气质

- 暖米白纸张底色，带极轻的自然纤维感。
- 手绘水彩果树作为核心视觉资产，笔触真实、色彩克制。
- 深植物绿承载品牌标题、导航选中态和成长信息。
- 番茄橙红只用于最重要的行动和截止提醒。
- 阳光黄、嫩芽绿、家庭蓝作为少量语义点缀。
- 大留白、清晰分隔线、弱阴影、克制圆角。
- 禁止大面积玻璃拟态、霓虹渐变、发光描边、胶囊堆叠和模板化 AI 插画拼贴。

### 3.2 核心颜色令牌

| 令牌 | 建议值 | 用途 |
|---|---:|---|
| `paper` | `#FAF7EE` | 全局页面底色 |
| `paperRaised` | `#FFFDF7` | 表单、弹层和高层级内容 |
| `ink` | `#20231E` | 主正文 |
| `inkMuted` | `#6F7068` | 次级说明、时间和辅助信息 |
| `forest` | `#174E2A` | 品牌标题、导航选中和成功成长 |
| `leaf` | `#6E923C` | 次级成长状态和插画配色 |
| `sproutTint` | `#EEF3DE` | 学校任务、成长提示浅底 |
| `tomato` | `#D93A22` | 主要按钮、当天截止和强提醒 |
| `sun` | `#F2A326` | 阳光、奖励和注意提示 |
| `familyBlue` | `#256A92` | 家庭来源标签 |
| `line` | `#DED8C9` | 列表分隔、表格边框 |
| `danger` | `#B9362C` | 删除、停用和安全风险 |

实现时允许根据真机和浏览器色差做小幅校正，但角色语义不得互换。

### 3.3 字体

- 正文使用系统中文无衬线字体，确保小字号和长列表清晰。
- 大标题、果树名称和成果卡片使用可商用的中文宋体/手写感展示字体。
- 书法感只出现在短标题，不能用于说明、表单、按钮和表格。
- 数字进度使用清晰的等宽感数字样式，突出 `18 / 30`、任务数量和时间。
- 不依赖 emoji 充当正式图标。

### 3.4 圆角、边框与阴影

- 任务列表优先使用分隔线，不把每行都做成独立悬浮卡片。
- 信息提示卡使用 12–16rpx 移动端圆角；弹层和大面板使用 20–24rpx。
- 管理后台卡片使用 8–12px 圆角，表格保持平整。
- 阴影仅用于弹层、浮动操作和关键菜单；普通内容不使用浓重阴影。

## 6. 关键页面设计

### 6.1 孩子“今日”首页

严格参考用户提供的视觉：

- 顶部显示日期、问候和“果园日计划”类标题。
- 上半屏为当前果树插画、果树名称、等级、阳光进度和距离成熟提示。
- 成长指南以一张浅色横卡表达新手树与普通树节奏。
- 下半屏为今日任务，按今日必做、家庭重点、额外挑战排序。
- 任务行展示来源、学科/类型、标题、要求、截止时间和唯一主要动作。
- 已提交行不再显示“去完成”，改为“待确认·阳光已保护”。
- 底部提示成人确认后阳光进入果树，不承诺尚未获得的资产。

### 6.2 任务提交

- 详情页先展示任务原文、来源、发布者、截止时间和提交要求。
- 根据 `submissionMode` 显示确认、文字、照片或组合输入。
- 拍照前展示用途和保存期限；上传中显示真实进度。
- 提交成功后返回明确状态，不立即伪造阳光到账。
- 需要订正时保留上一版证据，并突出教师反馈与再次提交入口。

### 6.3 家长审核

- 待审核列表按孩子与等待时间组织，可快速切换孩子。
- 审核详情同时展示任务要求、提交内容、任务来源和奖励状态。
- 家庭任务提供“确认完成、请补充、本次免除”。
- 机构任务明确区分教师学习评价和家庭阳光确认，避免家长误改教师状态。
- 默认阳光自动带入；调整时展示家庭规则来源。

### 6.4 教师工作台

- 顶部显示当前分组和今日三项计数：待审核、今日截止、需订正。
- 学生提交按任务分组，避免先展示全量学生名单。
- 审核操作为“学习完成、需订正、本次免除”，与家庭奖励分区展示。
- 完成第一次学习确认时提示“已为分组果树增加 1 次成长贡献”，不展示贡献排名。

### 6.5 管理后台工作台

- 顶部使用小幅果树插画和当天摘要，不占据主要工作面积。
- 主体使用克制卡片、表格、筛选栏和批量操作。
- 状态颜色沿用移动端语义，但红色只用于风险和关键行动。
- 表格必须支持空状态、加载、分页、筛选、权限拒绝和导出审批状态。

## 7. 核心操作闭环

### 7.1 孩子闭环

`今日任务 → 查看详情 → 提交 → 阳光资格保护 → 成人审核 → 阳光到账 → 果树成长 → 成熟采摘`

### 7.2 家长闭环

`切换孩子 → 查看待处理事项 → 审核提交 → 采用/调整默认阳光 → 查看成长结果`

### 7.3 教师闭环

`选择分组 → 创建/识别任务草稿 → 确认发布 → 自动分发 → 学习审核 → 共育树贡献`

### 7.4 入组闭环

`教师生成邀请 → 家长扫码 → 选择孩子 → 查看披露范围 → 家长同意 → 教师审批 → 建立机构成员关系`

### 7.5 客服访问闭环

`工单 → 申请精确资源授权 → 平台审批 → 限时读取 → 自动过期 → 审计留痕`

## 8. 年龄适配

产品不分裂成两套主题，而是在同一设计系统中提供两档信息密度。

### 8.1 低年级模式

- 更大果树和任务图标。
- 单屏只突出一个主要动作。
- 文案短、具体、鼓励式。
- 成长反馈更明显，但不使用婴幼儿拟声词和夸张卡通角色。

### 8.2 高年级模式

- 缩小装饰插画，提高任务与时间信息密度。
- “今日任务”可显示为“今日计划”，“成长卡片”可显示为“成长记录”。
- 强调目标、自主选择、连续记录和个人回顾。
- 保留水彩自然风格，不改成幼儿动画，也不做公开竞争。

默认根据孩子年级选择建议密度，家长和孩子可在设置中调整；该选择只影响表现，不改变业务规则。

## 9. 状态、错误与反馈

每个关键页面必须覆盖：

- 首次加载和骨架状态
- 空数据状态
- 网络离线和重试
- 云函数超时
- 权限失效
- 邀请过期或已使用
- 配额不足
- 图片上传中、失败和重试
- OCR 草稿待确认
- 重复提交/审核的幂等结果
- 成功、等待审核、需订正、已免除和已取消

错误文案使用用户可行动的语言。例如“这个邀请已过期，请联系老师重新生成”，不显示内部异常或数据库信息。

## 10. 动效原则

- 叶片轻摆：低频、可关闭，不干扰阅读。
- 阳光到账：从提示位置飞入当前果树，随后进度和阶段更新。
- 成熟采摘：作为独立庆祝时刻，不自动跳过。
- 未提交回流：表现预计阳光回到公共果园，不出现扣除、损失或他人抢走文案。
- 页面转场：150–240ms；成长反馈 500–900ms；完整庆祝不超过 2.5 秒。
- 尊重系统减少动态效果设置，关闭后用静态状态变化和文字反馈替代。

## 11. 无障碍与可用性

- 正文、状态和按钮满足清晰对比度，不仅依赖颜色区分。
- 移动端主要触控区域不小于 88rpx。
- 任务截止、来源和状态同时使用文字与图形。
- 图片上传、OCR 和审核均提供明确的取消、重试和返回路径。
- Web 后台支持键盘焦点、表单标签、表格标题和非鼠标操作。
- 装饰插画不抢占读屏顺序；重要成长结果提供文本描述。

## 13. 技术边界

### 13.1 小程序

- 保持原生微信小程序、TypeScript、WXML 和 WXSS。
- 页面只通过既有 `miniprogram/services/core-api.ts` 调用 `coreApi`。
- 主题令牌集中定义并输出为 WXSS 变量/类，不在页面散落颜色和间距常量。
- 可使用 TDesign MiniProgram 作为基础交互组件，但通过主题与自有业务组件实现参考图风格，不直接呈现默认组件库外观。

### 13.2 Web 管理后台

- 新增独立 TypeScript Web 应用，优先采用 React + Vite。
- 通过与小程序相同的命令契约访问后端，不直接读写 CloudBase 集合。
- 使用共享的语义令牌和客户端安全类型，移动与 Web 组件实现彼此独立。
- 管理后台认证和 CloudBase Web 调用适配在实施计划中单独验证，不能复用小程序 `OPENID` 假定。

### 13.3 数据与权限

- UI 不计算阳光、不推进果树、不批准成员关系、不决定租户权限。
- 角色切换只是导航偏好，服务端重新验证每个动作。
- 机构页面只使用 `organizationMemberId`，不显示全局 `childId`。
- 平台、机构和内容方页面不缓存儿童正文到不受控本地存储。

## 14. 测试与设计验收

### 14.1 自动化

- 主题令牌和组件契约测试。
- 角色导航与工作空间切换测试。
- ViewModel 到页面状态的映射测试。
- 提交、审核、邀请、上传和权限失败交互测试。
- 低/高年级密度模式测试。
- 小程序与 Web 构建、类型和现有 140 个业务回归测试。

### 14.2 视觉验收

- 以用户参考图为孩子“今日”首页的主要对照。
- 对同一视口和同一数据状态截屏比较。
- 首屏果树、标题、阳光进度、任务列表和底部导航不得明显偏离视觉比例。
- 所有插画使用最终资产，不以占位框、emoji 或 CSS 图形通过验收。
- 设计 QA 记录所有 P0–P3 差异；P0、P1、P2 清零后才能交付。

### 14.3 人工验收

- 低年级孩子能在不解释的情况下找到第一个任务并提交。
- 高年级孩子不认为页面幼稚。
- 家长能在一分钟内完成一次审核。
- 教师能清楚区分学习审核与家庭阳光。
- 机构管理员能完成分组创建、教师分配和任务筛选。
- 平台客服未取得授权时无法进入儿童内容。

## 15. 实施顺序

1. 建立共享视觉令牌、字体、图标和插画资产规范。
2. 完成孩子端“今日任务到果树成熟”的完整视觉闭环。
3. 完成家长端任务创建、审核、愿望和授权。
4. 完成教师/助教端分组、发布、审核和共育树。
5. 建立 Web 管理后台壳层和共享设计系统。
6. 完成机构管理员、平台运营和内容方页面。
7. 补齐全部错误、空状态、年龄适配、无障碍和动效降级。
8. 对照参考图执行视觉 QA，并在真机和桌面浏览器完成验收。

## 16. 当前范围边界

本轮 UI 全覆盖指已实现业务能力的所有角色和页面状态，不新增以下业务：

- 好友、聊天、评论、点赞和公开动态
- 孩子排行榜、个人贡献排名和组间竞赛
- 阳光购买、交易、现金兑换和广告奖励
- 惩罚性扣除、果树枯萎和成长倒退
- 未经家长授权的机构绑定
- 第三方读取儿童原始数据
- 正式支付、套餐定价和内容分成规则

最终产品名称、Logo、更多果树品类和商业定价可以后续替换或扩展，不阻塞本轮 UI 工程。
