# 儿童成长果园平台总体设计

> 日期：2026-09-05
>
> 状态：主体架构与核心功能已在产品讨论中确认；视觉风格待后续单独确认。
>
> 内部代号：成长果园。正式产品名称另行确定。

本规格描述新的目标架构。仓库中原“单家庭积分打卡 V1”文档保留为历史方案；本规格经用户书面复核后，后续实施以本规格为准。

## 1. 产品定位

这是一个面向小学生、家长、学校和辅导机构的任务协作与成长激励平台。

孩子完成真实任务并提交，家长、教师或助教按权限审核；通过审核后，孩子获得阳光，快速培育果树。成熟果树进入个人果园，形成长期可见、不会倒退的成长记录。

产品优先级：

1. 真实任务清晰、容易完成和审核。
2. 家长、教师与机构能够协作，但数据严格隔离。
3. 游戏反馈及时、正向，不使用惩罚性扣除或公开竞争。
4. 架构支持后续机构商业化、第三方内容与运营管理。

## 2. 已确认的核心原则

- 家庭与学校/辅导机构都是一级空间，彼此平行。
- 班级、辅导班和学习组是机构下的二级分组。
- 教师和助教是分组内的管理角色，业务上属于第三级管理层。
- 孩子是家庭、家长、教师、分组与机构之间的唯一连接中心。
- 一个孩子只有一个个人任务中心和一个个人果园。
- 机构只能查看本机构产生的任务、提交和学习记录。
- 家长可以查看自己孩子全部来源的任务，但不能修改教师发布的原始内容。
- 机构任务到达开始日或截止日后，默认进入孩子的“今日重点”；家长只处理例外。
- 已提交任务的阳光资格受到保护，不因家长或教师审核延迟而消失。
- 已入账阳光不扣除，果树不倒退、不枯萎。
- 不做好友偷取、孩子排行榜、公开比较、聊天和现金化奖励。

## 3. 产品空间与身份模型

### 3.1 一级空间

#### 家庭空间

- 一个家庭可包含多个孩子和多个监护人。
- 家庭管理员可以邀请其他监护人。
- 家庭任务、家庭奖励、愿望和完整个人果园仅家庭成员可见。

#### 学校或辅导机构空间

- 一个机构可包含多个分组、教师、助教和机构管理员。
- 学校与辅导机构使用同一套租户模型，通过机构类型区分。
- 机构的数据、统计、配置和成员关系必须与其他机构隔离。

### 3.2 二级分组

分组类型包括学校班级、辅导班、兴趣组和临时学习组。分组归属于且仅归属于一个机构。

### 3.3 用户与角色

一个微信用户账号可以同时拥有多个角色，例如既是家长又是教师。不同角色通过工作空间切换进入，权限与数据不能混用。

核心角色：

- 孩子
- 家庭管理员
- 家庭监护人
- 教师
- 助教
- 机构管理员
- 平台运营人员
- 第三方内容服务方

### 3.4 孩子身份隔离

- 平台内部使用全局唯一 `childId` 连接孩子的授权关系和个人资产。
- `childId` 永不向机构、教师或其他家庭公开。
- 每个机构为孩子生成独立的 `organizationMemberId`。
- 机构只能凭本机构成员编号访问获授权数据，不能跨机构查询孩子。
- 家长可授权向某机构显示姓名或昵称、年级、班内学号和可选头像。

## 4. 邀请、授权与退出

### 4.1 加入分组

1. 教师或机构创建分组。
2. 系统生成带有效期的二维码或邀请码。
3. 家长在家长身份下扫码，选择或创建孩子。
4. 页面展示机构、分组、教师和数据授权范围。
5. 家长确认并提交加入申请。
6. 教师或助教审核后，建立孩子与分组的成员关系。

不开放按名称公开搜索班级，也不允许机构绕过家长授权直接绑定完整孩子账号。

### 4.2 批量建班预留

机构可批量创建“待认领学生席位”，每个席位只有机构内部编号和一次性认领码。家长认领后才建立平台孩子关系。

### 4.3 退出与撤销授权

- 家长可以让孩子退出分组并撤销后续数据授权。
- 退出后不再接收新任务，也不能进入该分组页面。
- 孩子的个人阳光、果树和水果永久保留。
- 历史分组统计按机构保留策略匿名化，不继续暴露孩子身份。

## 5. 任务模型

### 5.1 任务来源

- 家庭任务
- 学校班级任务
- 辅导机构任务
- 学习组任务

每个任务必须记录来源空间、发布人、适用孩子或分组、科目/类型、时间和审核规则。

### 5.2 创建方式

- 手动创建
- 从模板创建
- 上传照片识别生成草稿

照片识别只能生成草稿，发布者必须确认标题、任务项、日期、科目和提交要求后才能发布。具体识别服务在照片任务子项目中确定，不进入首个开发切片。

### 5.3 任务字段

- 标题与说明
- 来源空间与分组
- 学科或生活分类
- 开始时间、截止时间和提醒时间
- 单次、每日或指定星期周期
- 必做或额外挑战
- 预计用时
- 阳光规则引用
- 提交方式：仅确认、文字、照片或组合
- 是否允许补交
- 是否需要教师学习反馈
- 发布、取消和归档状态

### 5.4 模板与任务实例分离

- `task_templates` 保存可复用规则，不代表某个孩子当天必须完成。
- `tasks` 保存一次发布行为。
- 发布后，为每个孩子创建独立 `task_assignment`。
- 每个孩子的提交、审核、请假、补交和阳光状态互不影响。

这一分离必须从首版开始采用，避免后续班级发布和周期任务无法扩展。

## 6. 今日重点

### 6.1 自动进入

- 家庭任务创建后进入对应孩子的任务中心。
- 分组任务发布后自动进入所有有效成员的任务中心。
- 到达开始日或当天截止的必做任务，自动进入“今日必做”。
- 尚未到开始时间的任务进入“即将开始”。
- 家长不需要再次添加机构任务。

### 6.2 页面分层

孩子端今日任务分为：

1. 今日必做：今天需要完成的家庭或机构任务。
2. 家庭重点：家长强调的 1 至 3 项任务。
3. 额外挑战：完成有奖励，但不影响“今日全完成”。

### 6.3 例外规则

- 请假或本次免除的任务不计入今日全完成。
- 发布者取消任务后不计为未完成。
- 已提交但未审核的任务按“已履行等待确认”展示，资格受到保护。
- 以 `Asia/Shanghai` 为日历时区。当天 18:00 后发布且要求当天完成的任务，默认不计入当日“全部完成”条件；家长或孩子主动接受为今日挑战时除外。
- 较晚发布的任务仍必须明确标记并通知家长，不能追溯取消孩子已经取得的当日全完成资格。

## 7. 提交与双状态审核

### 7.1 家庭任务

孩子提交后，由有权限的家庭监护人执行：

- 确认完成
- 请补充
- 本次免除

确认完成时按家庭奖励规则发放阳光。

### 7.2 机构任务

机构任务具有两个独立状态：

- 学习状态：由教师或助教标记为已完成、需订正或已免除。
- 家庭奖励状态：决定个人阳光是否入账。

规则：

1. 孩子提交后，待领取阳光立即受到保护。
2. 家长可以进行家庭确认并发放阳光。
3. 教师确认完成后，若家庭开启自动奖励，则按家庭默认值自动发放阳光。
4. 若教师之后要求订正，已经发放的阳光不追回。
5. 订正完成可按家庭规则获得少量额外阳光。
6. 家长不能修改教师的学习评价；教师不能查看家庭愿望和私人奖励配置。

### 7.3 状态分离

- 任务实例状态：`PENDING`、`SUBMITTED`、`REVISION_REQUIRED`、`COMPLETED`、`EXCUSED`、`CANCELLED`、`EXPIRED`。
- 学习审核状态：`NOT_REQUIRED`、`PENDING`、`APPROVED`、`REVISION_REQUIRED`、`EXCUSED`。
- 家庭奖励状态：`NOT_ELIGIBLE`、`PROTECTED`、`PENDING_CONFIRMATION`、`GRANTED`、`WAIVED`。

三个状态分别回答“任务进行到哪一步”“教师如何评价学习结果”“家庭阳光是否发放”，不能合并为单一状态字段。

## 8. 阳光账本

### 8.1 阳光的性质

- 阳光是孩子完成真实任务后获得的成长值。
- 已入账阳光只累计，不进行惩罚性扣除。
- 阳光不能购买、转让、兑换现金或通过广告获取。
- 每笔阳光必须通过不可变账本记录来源、数量、审核者和关联任务。
- 阳光账本记录孩子终身累计获得量；当前果树进度只是账本事件的可重建投影，不代表消费或扣除。

### 8.2 家庭默认规则

每个家庭设置一次默认奖励，例如：

- 普通任务：2 阳光
- 重点任务：3 阳光
- 额外挑战：1 阳光
- 完成订正：1 阳光

机构发布者只设置任务强度、预计用时和重要性，不直接决定每个家庭的最终阳光数量。

### 8.3 待领取与回流

- 任务展示的预计阳光在审核前属于“待领取”，不是孩子已拥有资产。
- 未提交任务到家庭日终时间后，可播放阳光回到公共果园的动效。
- 已提交任务的待领取阳光不回流，持续等待成人确认。
- 公共阳光池是视觉与仪式机制，不是有限资源池，也不显示其他孩子信息。
- 未提交任务到期时只更新任务实例并产生一次回流动效事件，不写入负数阳光账本。

## 9. 个人成长果园

### 9.1 核心循环

`查看今日任务 → 完成并提交 → 成人确认 → 阳光入账 → 当前果树变化 → 果树成熟 → 采摘水果 → 果树进入个人果园`

### 9.2 成长节奏

- 新手苹果树默认需要 6 阳光，在首日完成 2 至 3 项任务后即可成熟。
- 普通果树默认需要 24 阳光，以 3 至 5 天完成为目标节奏。
- 稀有果树默认需要 60 阳光，以 7 至 14 天完成为目标节奏。
- 阈值通过果树目录配置，不写死在客户端。
- 单次入账超过当前果树剩余进度时，超出的阳光进入“待培育阳光”，在孩子选择下一棵树后自动接续，不丢失也不回退。

### 9.3 视觉成长节点

种子、破土、嫩芽、树干、长叶、花苞、开花、小果、果实变大、成熟采摘。每次阳光到账都应产生至少一个可感知的变化或进度反馈。

### 9.4 成熟与收藏

- 成熟果树进入个人果园永久展示。
- 孩子可以为果树命名并获得成长卡片。
- 成熟时获得对应水果并点亮图鉴。
- 旧果树不需要持续消耗阳光，也不会枯萎。
- 水果可由家庭选择是否关联家庭愿望；机构不可见愿望。

## 10. 分组共育果树

每个分组可以开启一棵共育果树：

- 孩子完成该分组任务时，个人果树正常获得阳光。
- 同时为该分组果树增加一次成长贡献，不扣个人阳光。
- 分组成长贡献在教师首次把学习状态确认成 `APPROVED` 时幂等生成；家庭提前发放个人阳光不会提前改变分组进度。
- 家庭任务不贡献到机构分组，避免机构推断家庭活动。
- 孩子只看到集体进度，不看到个人排名、谁未完成或谁贡献最多。
- 教师在权限范围内查看任务提交明细，但不能向孩子公开排名。
- 共育果树成熟后生成分组纪念卡、徽章或主题装饰。

首版共育范围限定为“一组一棵果树、集体进度、成熟纪念”，不做组间竞赛、点赞和聊天。

## 11. 权限矩阵

| 角色 | 可见范围 | 核心操作 |
| --- | --- | --- |
| 孩子 | 自己的任务、提交、阳光、个人果园和已加入分组的集体进度 | 提交任务、补充证据、选择果树、采摘水果 |
| 家长 | 自己孩子全部来源任务、提交、个人资产和授权关系 | 创建家庭任务、家庭审核、奖励设置、加入/退出分组 |
| 教师 | 自己负责分组内的机构任务、成员和学习提交 | 发布任务、学习审核、反馈、管理共育果树 |
| 助教 | 被授权分组内的任务和提交 | 协助发布、提醒和审核；无机构核心配置权限 |
| 机构管理员 | 本机构成员、分组和机构任务统计 | 创建分组、分配角色、配置机构规则 |
| 平台运营 | 租户状态、套餐、异常和审计元数据 | 账户治理、违规处理和服务配置；默认不读取儿童内容 |
| 内容服务方 | 自己发布的模板和结算数据 | 提交内容模板；不能获取儿童原始数据 |

所有权限由服务端根据当前账号、角色成员关系、空间范围和孩子授权关系共同判定。客户端隐藏按钮不构成安全边界。

## 12. 数据与服务架构

### 12.1 固定技术方向

- 客户端：原生微信小程序 + TypeScript。
- 后端：微信云开发 CloudBase。
- 客户端仅通过云函数访问业务数据。
- 敏感集合设置为仅管理端可读写。
- 所有命令带 `requestId`，写操作必须幂等。
- 涉及审核、阳光和果树成长的写入使用事务或可重放事件保证一致性。

### 12.2 领域模块

1. 身份与租户：账号、家庭、机构、角色和成员关系。
2. 孩子授权：孩子、监护关系、机构成员别名、邀请和同意记录。
3. 任务中心：模板、任务发布、孩子任务实例、今日投影和提醒。
4. 提交审核：提交材料、学习审核、家庭确认和订正。
5. 阳光账本：待领取资格、阳光流水、幂等发放和统计投影。
6. 果园引擎：果树目录、成长实例、阶段、成熟和水果收藏。
7. 分组共育：分组果树、贡献事件和集体成果。
8. 媒体任务：照片上传、保存期限、识别草稿和删除。
9. 审计治理：敏感操作日志、客服临时访问和数据导出记录。
10. 商业能力：套餐权益、功能开关、机构配额和内容服务方接入。

模块通过明确命令与事件交互，不允许页面直接修改账本余额、果树进度或跨租户成员关系。

### 12.3 核心集合

| 领域 | 集合 |
| --- | --- |
| 身份与租户 | `accounts`, `families`, `family_members`, `organizations`, `organization_members`, `groups`, `group_role_bindings` |
| 孩子授权 | `children`, `guardian_links`, `child_group_memberships`, `invitations`, `consent_records` |
| 任务 | `task_templates`, `tasks`, `task_assignments`, `submissions`, `review_records` |
| 激励与果园 | `sunlight_ledgers`, `tree_catalog`, `child_trees`, `fruit_collections`, `group_trees`, `group_contributions` |
| 媒体与治理 | `media_assets`, `task_drafts`, `audit_logs`, `support_access_grants` |
| 商业配置 | `plans`, `tenant_entitlements`, `usage_counters`, `content_providers` |

具体字段、索引和事务边界在实施计划中逐模块展开。

## 13. UI 解耦策略

视觉风格尚未最终确认，因此首期开发遵守以下边界：

- 业务状态、权限判断、奖励计算和果树成长不写入页面组件。
- 页面只通过领域服务和页面 ViewModel 读取可展示状态。
- 颜色、字号、间距、圆角和动效时长统一由设计令牌控制。
- 通用按钮、表单、弹窗、上传、日历和标签通过组件适配层调用。
- 技术基线优先采用 MIT 协议、原生微信小程序可用的 TDesign MiniProgram；最终视觉通过主题令牌和自有业务组件实现。
- WeUI、Vant Weapp 与其他开源项目仅作交互与组件参考，不在同一页面混装多个组件库。
- 果树、果实和成长动效为自有资产层，不能与组件库耦合。

因此后续更换整套 UI 时，不需要重写权限、任务、审核、阳光账本和果园引擎。

## 14. 隐私、安全与治理

- 默认最小化采集儿童数据。
- 机构访问必须经过家长授权并受租户范围限制。
- 任务照片和作业证据启用后必须记录所属空间、可见角色、保存期限和删除状态。
- 平台客服默认不可查看儿童任务内容；临时访问必须基于工单、限定范围和时间，并写入审计日志。
- 日志不得记录 PIN、完整儿童资料、上传文件原文或云端密钥。
- 家长拥有查看授权、撤销授权、删除申请和本人家庭数据导出入口。
- 机构导出必须受权限、审批和下载留痕约束。

## 15. 商业化预留

### 15.1 家庭会员

- 更多家庭成员协作
- 高级任务模板
- 更多果树与果园主题
- 成长周报和历史导出

### 15.2 机构 SaaS

- 多分组和多教师管理
- 批量任务发布与审核
- 合规范围内的学习统计
- 角色权限、审计和导出
- 机构品牌配置

### 15.3 第三方内容

- 第三方只提供任务模板、课程内容或果树主题。
- 第三方默认不能获取儿童原始任务、提交照片和家庭愿望。
- 平台通过套餐权益与内容授权控制可用范围。

不通过出售阳光、儿童广告、排名付费或儿童数据变现。

## 16. 分阶段实施

### 阶段 A：平台底座与家庭闭环

- 项目骨架、CloudBase 环境和本地测试框架
- 账号、家庭、多孩子和监护关系
- 任务模板、任务实例和今日重点
- 孩子提交、家庭审核和阳光账本
- 第一棵快速果树与普通果树成长
- UI 仅使用可替换的基础组件和设计令牌

### 阶段 B：机构与分组协作

- 学校/辅导机构、分组、教师和助教角色
- 邀请码、家长授权和退出
- 分组任务自动分发
- 学习状态与家庭奖励双状态审核
- 分组共育果树

### 阶段 C：照片与任务草稿

- 成人上传任务通知或黑板照片
- 图片权限、压缩、保存期限和删除
- 识别为可编辑任务草稿
- 孩子上传作业证据

### 阶段 D：商用管理

- 机构管理后台
- 套餐、配额和功能开关
- 统计、导出审批和审计
- 第三方内容服务方接入

每个阶段都必须交付可运行的纵向闭环，不以只有数据表或静态页面作为完成标准。

## 17. 首个开发切片

首个开发切片为“家庭任务到第一棵果树成熟”：

1. 家长创建家庭和孩子。
2. 家长创建今日任务并使用默认阳光规则。
3. 孩子进入自己的今日任务页并提交。
4. 家长审核通过。
5. 系统幂等写入阳光账本并推动当前果树成长。
6. 孩子在首日完成 2 至 3 项任务后完成第一棵果树并采摘水果。

同时预埋 `tenantScope`、发布来源、任务实例和审核类型字段，确保阶段 B 无需重建核心数据。

## 18. 验收标准

### 18.1 功能

- 一个家庭可管理多个孩子，孩子数据不会串联。
- 同一任务发布给多个孩子后，每个孩子状态独立。
- 到期机构任务无需家长操作即可进入今日重点。
- 家庭任务由家长审核；机构任务保留学习与奖励两个状态。
- 重复提交、重复审核或网络重试不会重复发放阳光。
- 已提交任务在审核延迟期间不失去阳光资格。
- 阳光流水可追溯且不能被客户端直接改余额。
- 首棵树可首日成熟，普通果树配置为 3 至 5 天节奏。
- 退出机构不会删除孩子个人果园资产。

### 18.2 权限

- 教师不能读取家庭任务、愿望和其他机构数据。
- 机构管理员不能通过平台孩子 ID 跨机构查询。
- 家长只能管理与自己具有有效监护关系的孩子。
- 平台运营默认不能读取儿童任务正文和照片。

### 18.3 体验

- 孩子首页首先呈现今日任务和明确提交动作。
- 家长不需要逐条把机构任务加入今日重点。
- 每次有效阳光到账都有可感知的果树进展。
- UI 主题替换不改变任务、审核和阳光业务测试。

## 19. 明确不纳入当前范围

- 好友系统和真实偷取
- 孩子公开排行榜或组间排名
- 聊天、评论、点赞和公开动态
- 阳光交易、现金兑换、抽奖购买和广告换次数
- 惩罚性扣除已获得阳光
- 果树枯萎或成长倒退
- 未经家长授权的机构绑定
- 第三方直接读取儿童原始数据
- 首个开发切片中的照片识别、支付和完整 Web 管理后台
