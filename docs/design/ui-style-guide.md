# 成长果园小程序 UI 统一规范

## 1. 设计目标

本小程序的视觉语言是“温暖、自然、轻量的成长果园”。页面应让家长、老师和孩子首先感到清晰、可信、易操作，而非进入传统管理后台。

业务逻辑仍以当前 MVP 为准：用户首次进入可直接浏览首页；只有创建任务、管理资料、加入分组等会写入个人数据的动作，才要求微信登录。

## 2. 全局视觉令牌

| 用途 | 规范 |
| --- | --- |
| 页面底色 | 暖米白、纸张感背景，避免纯白或冷灰大面积铺底。 |
| 主文字 | 深墨绿/近黑色，用于标题和关键内容。 |
| 品牌与确认 | 森林绿，用于导航选中、次要操作、成功和已保护状态。 |
| 主操作 | 番茄红，用于创建、提交、立即完成等唯一主操作。 |
| 成长激励 | 暖橙/日光黄，用于阳光、进度和成长反馈。 |
| 任务分类 | 家庭任务使用浅蓝与蓝色强调；学校任务使用浅绿与森林绿强调。 |
| 分割与边框 | 低对比暖灰细线；不使用生硬的深灰边框。 |
| 圆角 | 控件约 `14rpx`，普通卡片约 `18rpx`，弹层可更大；同类组件必须一致。 |

## 3. 排版与留白

- 页面左右内边距统一约 `36rpx`；区块间距约 `34rpx`；卡片内边距约 `28rpx`。
- 页面标题约 `36rpx`、深色、偏粗；正文约 `27rpx`；说明和辅助信息使用 `21–24rpx` 的低对比灰绿色。
- 首页果园标题使用现有手写标题素材，不能以普通系统标题替代；其他页面优先使用统一文字标题。
- 内容按“标题/说明 → 内容区 → 明确操作”的阅读顺序组织，避免一屏出现多个同等重要的大按钮。
- 文字、图标和按钮文案必须水平与垂直居中；长文案应先换行或收缩版面，不能挤压插画或超出容器。

## 4. 页面骨架

### 首页与一级页面

- 首页不显示系统默认标题栏，进入即呈现果树、今日任务和成长信息，满足审核时无需先登录即可浏览的要求。
- 一级页面使用底部 Tab；内容底部应预留足够空间，不能被 Tab 遮挡。
- 首页可以使用果树与成长插画作为视觉中心，但信息仍需在插画之外可读、可操作。

### 二级功能页

- 使用轻量的返回区、页面标题和一句说明；不要复用首页的大型果树头图。
- 表单、详情、分组和设置页以暖白内容卡片和分隔行组织，强调任务本身而非装饰。
- 存在不可逆或需要登录的动作时，在点击动作后再承接登录/确认，不在页面进入时强制打断浏览。

## 5. 组件规范

### 卡片与列表

- 普通信息使用暖白卡片、细暖灰边框和轻圆角。
- 任务列表优先使用“标题 + 状态 + 操作”的分隔行，不要让每一条任务都成为厚重的悬浮大卡片。
- 柔和色块卡片仅用于成长提示、统计或引导，不能替代所有信息容器。
- 空状态应延续果园插画语言，并提供一句温和引导和一个明确下一步按钮。

### 按钮

- 主按钮：番茄红底、白字、约 `88rpx` 最小高度、圆角控制一致。
- 次按钮：暖白底、森林绿描边和文字；仅在主操作之外使用。
- 单个操作区原则上只有一个主按钮；禁用状态以低对比色和不可点击反馈表达。
- 所有按钮文字必须居中，点击区保持充足，避免只让小图标可点击。

### 状态与标签

- 使用短文字与颜色共同表达，例如“进行中”“待提交”“阳光已保护”；不可只用颜色传递状态。
- 统一用小圆角 Pill 承载轻量状态，不将状态做成大面积色块。
- 成功、提醒、风险分别使用森林绿、暖橙和克制的红色；避免在同一区域混用过多高饱和色。

### 表单与设置

- 输入框、选择器与上传入口使用统一暖白底、细边框、约 `14rpx` 圆角和不少于 `88rpx` 高度。
- 设置项使用最小高度一致的分隔行，左侧为名称/说明，右侧为当前值、箭头或开关。
- 错误提示紧贴字段、用清晰文字说明如何修正；不可只显示红框。

## 6. 图标、插画与底部导航

- 必须复用源分支已迁移的果园插画，以及苹果、果树、用户三枚底部导航图标资源。
- 不使用 Emoji、Unicode 字符、临时 CSS 绘制图标或其他库的替代图标，以避免平台显示差异和风格漂移。
- 底部 Tab 为暖白半透明底、顶部细分割线；选中态为森林绿、文字加粗并带细下划线，未选中为灰绿色。
- 底部 Tab 只服务一级页面。二级页面由返回操作承担导航，不能叠加不相关的底部入口。

## 7. 动效与反馈

- 动效只用于阳光增加、果树成长、任务完成等正反馈，保持短促、轻量、可打断。
- 页面加载、提交和上传都要有明确进行中与失败反馈；不要以无响应代替加载状态。
- 不使用持续闪烁、大范围漂浮或会妨碍阅读和操作的装饰动效。

## 8. 页面验收清单

后续新增或调整页面时，至少确认：

1. 是否使用暖纸张背景、统一色彩语义、留白与圆角；
2. 是否只有一个清晰的主操作，且按钮文案居中；
3. 是否优先使用现有任务行、卡片、标签、表单和底部导航组件；
4. 是否没有新增 Emoji、临时图标或与果园主题冲突的视觉资产；
5. 一级页面是否预留底部 Tab 空间，二级页面是否提供明确返回；
6. 是否保留“先浏览、后在写入动作时登录”的 MVP 审核逻辑；
7. 是否在微信开发者工具中检查了窄屏、长文案、加载、空状态和失败状态。

## 9. 禁止项

- 不把首页改为登录页、角色选择页或传统后台仪表盘。
- 不为追求统一而在每个页面重复果树大插画。
- 不使用高饱和渐变、厚阴影、花哨玻璃拟态或多个抢眼色块。
- 不把底部导航图标替换为非源分支资源。
- 不在没有业务必要时增加登录、权限或确认步骤。
